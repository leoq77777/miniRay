# Fault tolerance

每个任务有稳定 task ID、递增 attempt ID 和当前 worker ID。结果必须精确匹配三者，且任务处于 DISPATCHED/RUNNING 才能生效。重复终态上报返回 accepted=false，但 RPC 成功，worker 不需再发送。旧代、未来代、错误 worker 和终态逆向变更全部拒绝。

心跳过期在同一状态锁内完成 worker 隔离及其所有运行任务的重排。任务每次进入重试队列立即递增 attempt ID，因此即使尚未重新派发，旧结果也无法写入。重试耗尽或任务禁止重试时转 FAILED。网络层派发失败可能是“请求已执行、确认丢失”，同样递增代际后重试，不能假定没有执行过。

派发失败后，协调器把该目的地暂时排除调度一个心跳超时周期，让重试优先使用其他健康 worker，避免在死亡检测前对同一目的地快速耗尽预算。冷却不丢弃该 worker 上其他任务的预留或合法结果；心跳过期仍会按常规恢复它们。

worker ID 标识进程 incarnation，自动随机生成。过期 ID 永久拒绝重注册，避免网络分区后的旧执行占用不可见容量；旧 worker 收到 FAILED_PRECONDITION 后隔离并拒绝新任务，需要重启生成新 ID。已有执行可能继续并产生副作用，attempt 隔离只保证结果记录正确，无法撤回外部写入。

worker 结果上报失败会重发同一结果，最多 10 次（每次 RPC 500ms，间隔 100ms）。持续失败后停止心跳并拒绝新任务，让协调器超时回收未完成任务，避免“心跳还活着但任务结果永远丢失”。协调器关闭将未终结任务标为失败并唤醒等待者，但不做持久化。

默认故障窗口为 2500ms 心跳超时，加调度线程扫描延迟。空闲时每 10ms 扫描一次；同步派发 RPC 的 200ms 截止时间会增加扫描延迟。故障检测是怀疑机制，实际网络延迟可能导致误判；生产化需要更完整的控制面隔离和租约设计。

验证：

```sh
ctest --test-dir build --output-on-failure
```

单元测试通过可注入时间验证超时、代际隔离、预算和终态；RPC 测试验证真实服务、异常、客户端超时后继续查询及并发容量；process-recovery 启动真实二进制，等待任务确认开始后 SIGKILL worker，启动替代 worker，断言相同 task ID 在 attempt 1 完成，然后验证 SIGTERM 对执行中任务的优雅排空。
